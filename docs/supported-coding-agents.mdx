## OpenCode v2

Install `@opencode/cli@2.4.1` in a separate npm prefix on the execution host. In **Settings → Agents**, set the OpenCode v2 base command to the absolute path to that installation’s `opencode2` executable. This keeps the `opencode` command for existing v1 profiles. Select **OpenCode v2** in the workspace or session, or use `--executor OPENCODE_V2` in `vk`.

You can use provider API keys carried in the executor environment. To use credentials from `/connect`, set a dedicated `XDG_DATA_HOME` in the OpenCode v2 profile and run `opencode2` with that same setting. Vibe Kanban otherwise uses its own v2 data directory. Keep your OpenCode configuration compatible with v1 if both versions read it. [OpenCode v2 migration and configuration](https://opencode.ai/docs/migrate-v1/)

OpenCode v2 supports native session resume, interruption, the context usage gauge and the commands it lists, including your project and user commands, in the chat's `/` menu. `/compact` compacts the session. With **Supervised**, Vibe Kanban asks before edits, shell commands, web access and access outside the workspace, unless a rule in your OpenCode configuration already allows or denies the action. **Auto** approves the remaining requests and shows the agent's questions in the chat. **Don't Ask** also approves them but stops the agent from asking questions. In every mode, deny rules in your configuration still apply. OpenCode's plan agent is available in the agent selector; the **Plan** permission policy is refused. When the commit reminder is on and a turn leaves changes, Vibe Kanban sends the reminder once in the same session. Choose **OpenCode** to continue existing v1 sessions and profiles.

Vibe Kanban offers the same prompt edit and rewind targets as for Claude Code
and Codex. Reset updates Vibe Kanban history and optionally restores files
without calling OpenCode. On the next prompt, OpenCode forks before the first
dropped message when a native boundary is available; if the fork fails, the
prompt is not sent on the old session. When a native session exists but its
matching message boundary is unavailable, reset is refused to prevent hidden
messages returning in the agent context. Start a new session instead. Stop a
running turn before resetting.

### Sync repository memory

In **Settings → Automation → Agent Memory Sync**, enable reconciliation and select **OpenCode v2** on each participating host. The first sync creates a [project skill](https://opencode.ai/docs/skills/) at `.opencode/skills/vibe-repository-memory/SKILL.md` in the registered checkout. OpenCode discovers it as `@vibe-repository-memory` in that checkout and in Vibe Kanban sessions for the same repository. In a workspace with several repositories, start the session in the worktree for the repository you want.

- To share new knowledge, add a `## Topic` section to the skill in the registered checkout, not a copy in the worktree. Include only durable information you want to share with the other executors.
- To correct or delete an authored topic, edit its body or remove its section, then sync again. Leave the skill frontmatter, scope comment, and identifiers for retained topics in place. Removing the entire file is treated as a missing local copy, not a request to delete remote memory.
- A correction remembers the old text. Lines that match a deleted or replaced topic exactly are also removed from other topics, and writing a deleted topic's text again is removed on the next sync. Reword the text to keep it.
- Close fenced code blocks before syncing. An unclosed fence stops synchronization rather than risking changes to the surrounding topics.
- To read imported memory, use `@vibe-shared-repository-memory`. If the imported topics together exceed 256 KiB, the generated skill keeps whole topics in alphabetical order and states how many were omitted. Your authored memory is not affected. Do not edit the generated skill. To change an imported topic, use **Memory corrections and deletions → One repository** in the same settings.

Sync keeps the two memory files out of Git through a local exclude rule and refuses to use tracked paths. If you register the same repository more than once on a host, sync uses the first registered checkout. Vibe Kanban uses those same files rather than copying them into linked worktrees. Sync does not read OpenCode's global instructions, global skills, plugins, session database or conversation history. For self-hosted installations, update the central server and all participating hosts before selecting OpenCode v2.

## Pi

Install `@earendil-works/pi-coding-agent@1.4.0` and `pi-acp@0.0.35` on the execution host. Sign in through Pi's `/login` command or provide a model provider's API key through the executor environment. Select **Pi** in the workspace or session, or use `--executor PI` in `vk`. [Pi ACP adapter](https://zed.dev/acp/agent/pi)

Pi supports model selection, streaming, native session resume, interruption, the context usage gauge, the commit reminder and the commands Pi announces in the chat's `/` menu. With **Supervised**, Vibe Kanban presents Pi extension confirmations and lets you choose an option from a Pi extension's selection request. **Auto** approves confirmations and still shows selection requests. **Don't Ask** approves confirmations and cancels selection requests. Pi has no plan mode, so the **Plan** permission policy is refused. Pi extensions control which tools require confirmation. Message-level rewind is unavailable.

## ZCode

Use the Z.ai ZCode CLI from the [FrontierHarness Eval source build](https://github.com/frontier-harness-eval/eval/blob/84a29789534af5b316df642be279c23c84caa2e4/suites/baseten-eval.json). The verified CLI is 0.17.0 at commit `3c5b227649371507ddc4eb46ac5133afe6db1cab`. Put its `zcode` command on PATH or set a base command override that runs the built `zcode.cjs` with Node.

Configure a model and credentials on the execution host using ZCode's personal provider configuration. You can pass the configuration path as `ZCODE_PERSONAL_PROVIDER_CONFIG_FILE` in the executor environment. Use a provider that supports tool calls for coding tasks. Models use `provider/model` identifiers. [ZCode provider configuration](https://github.com/zai-org/ZCode/blob/3c5b227649371507ddc4eb46ac5133afe6db1cab/apps/zcode-cli/docs/usage/03-config.md)

Select **ZCode** in the workspace or session, or use `--executor ZCODE` in `vk`. ZCode's stdio app server provides streaming, native session resume, interruption, tool approval, the context usage gauge, the commit reminder and the commands listed by the session in the chat's `/` menu. Vibe Kanban runs ZCode in build mode and approves requests itself under **Auto** and **Don't Ask**, so ZCode's deny rules still apply. **Auto** shows the agent's questions in the chat; **Don't Ask** declines them. The **Plan** permission policy is refused. Message-level rewind is unavailable.

## Chat features by agent

Claude Code, Codex, OpenCode (v1), Gemini CLI and Qwen Code already offer
prompt edit and retry through their existing session continuation paths.
Vibe Kanban does not enable those actions for an executor solely because its
interactive terminal supports undo or file checkpoints.

The context gauge shows the tokens currently in the conversation against the context window of the model that produced them. It is never filled from cumulative usage, cost, per-turn totals or an estimated limit. When an agent does not report both values, or the value is unknown after a model change or compaction, the gauge shows a placeholder instead of 0%.

The `/` menu lists only commands that the agent can run from chat. Commands that exist only in an agent's terminal interface, and `@` skill mentions, are not offered unless the agent's own protocol runs them from a prompt.

| Agent | Context gauge | `/` commands | Permission policies | Commit reminder |
| --- | --- | --- | --- | --- |
| Claude Code | Supported | Supported | Auto, Don't Ask, Supervised, Plan | Supported |
| OpenAI Codex | Supported | Supported | Auto, Don't Ask, Supervised, Plan | Supported |
| OpenCode | Supported | Supported | Auto, Don't Ask, Supervised. **Plan** is refused; choose OpenCode's plan agent | Supported |
| OpenCode v2 | Supported | Supported, including your project and user commands and `/compact` | Supervised, Auto, Don't Ask. **Plan** is refused; choose OpenCode's plan agent | Supported |
| Pi | Supported | Commands that Pi announces, including `/skill:name` | Supervised, Auto, Don't Ask. **Plan** is refused | Supported |
| ZCode | Supported | Commands that the session lists | Supervised, Auto, Don't Ask. **Plan** is refused | Supported |
| Gemini CLI | Not supported: version 0.29.3 reports no usage | Not supported: no command list over ACP in 0.29.3 | Auto, Supervised. Over ACP it cannot receive answers to questions, so Auto and Don't Ask behave the same. **Plan** is refused | Supported |
| Qwen Code | Not supported: version 0.9.1 reports no `usage_update` | Not supported: command output arrives only through a private notification | Auto, Supervised. It has no question tool, so Auto and Don't Ask behave the same. **Plan** is refused | Supported |
| GitHub Copilot CLI | Not supported: version 0.0.403 discards usage events | Not supported: no commands over ACP in 0.0.403 | Auto, Supervised. It has no question tool over ACP, so Auto and Don't Ask behave the same. **Plan** is refused | Supported |
| Amp | Not supported: no documented context window | Not supported: execute mode has no commands | Auto and Don't Ask run with `--dangerously-allow-all`, because execute mode cannot ask. **Supervised** and **Plan** are refused | Supported as an automatic follow-up turn |
| Cursor Agent | Not supported: stream-json has no context window | Not supported: no command list | Auto (print mode never asks, so Don't Ask is the same) and Plan (`--mode plan`). **Supervised** is refused | Supported as an automatic follow-up turn |
| Factory Droid | Not supported: stream-json has only cumulative totals | Not supported: no command list | Auto and Don't Ask (skip permissions). **Supervised** and **Plan** are refused | Supported as an automatic follow-up turn |

A refused policy fails the turn with a message that names it. Vibe Kanban never runs the turn under a different policy.

The commit reminder asks the agent to commit what it left uncommitted after a normal exit. Amp, Cursor Agent and Factory Droid end their process with each turn, so Vibe Kanban sends the reminder to them as an automatic follow-up message in the same session, once. A turn that fails, is stopped or runs a slash command gets no reminder, and neither does a quick chat or a one-off session.

<Note>
If changes are still uncommitted, Vibe Kanban commits them itself. It never uses the agent's final reply as the commit message. Every agent except Amp, Cursor Agent and Factory Droid first writes the message in a run with no tools: OpenCode v2 answers from the session without adding to it, OpenCode answers in a copy of the session that it then deletes, and the others use a fresh one-shot run that receives file names and change status. Amp, Cursor Agent and Factory Droid commit through the follow-up message, and anything that is still left gets the default message. The message follows your commit conventions and refers only to issue numbers that you wrote in the session. If the message cannot be written, or is not a commit message, the default message is used. One-shot runs of Pi, Gemini CLI, Qwen Code, GitHub Copilot CLI and ZCode can appear in that agent's own session history. A quick chat never commits your working tree.
</Note>
